# Архітектурні патерни бекенду

## Specification: фільтри каталогу

`QuizSpecifications` описує умови відбору квізів як окремі правила:

- `nameOrSubjectContains(search)` — пошук за назвою квізу або предмета;
- `hasAnyComplexity(levels)` — відбір за кількома рівнями складності;
- `matching(search, levels)` — поєднання цих правил через `and`.

Spring Data JPA перетворює специфікацію на SQL-предикати. Одна й та сама
специфікація використовується для вибірки сторінки та підрахунку всіх збігів.
Так умови основного запиту й `count` не потрібно підтримувати у двох JPQL-рядках.

```java
var filters = QuizSpecifications.nameOrSubjectContains("Java")
        .and(QuizSpecifications.hasAnyComplexity(List.of("low", "medium")));
var page = quizRepository.findCatalogue(filters, PageRequest.of(0, 20));
```

Незалежні правила можна також поєднувати через `or`. Публічний API, як і раніше,
застосовує `and`: кожен надісланий фільтр звужує результати.

Порожній фільтр повертає `Specification.unrestricted()`. Завдяки цьому до SQL
взагалі не додається `IN ()`, який MySQL не приймає. Спеціальна колекція-заглушка
та прапорець `allComplexities` більше не потрібні. Рівні нормалізуються через
`Locale.ROOT`, а `%`, `_` і `!` у пошуковому тексті екрануються.

Репозиторій відповідає за стабільне сортування за `id`. `@EntityGraph` завантажує
предмет і рівень разом із квізами, тож формування відповідей не створює запит
для кожного рядка. Fetch-план відокремлений від специфікації та її count-запиту.
Адміністративний каталог використовує той самий шлях без фільтрів.

Контрактні тести перевіряють композицію правил, буквальний пошук спецсимволів,
порядок і загальну кількість збігів на різних сторінках, завантаження зв'язків.
`QuizCatalogueIntegrationTest` додатково перевіряє запити на MySQL із production
Flyway-міграціями.

## Strategy: обмеження частоти запитів

`RateLimitService` має реалізації `InMemoryRateLimitService` і
`RedisRateLimitService`. `RateLimitConfiguration` обирає реалізацію за
конфігурацією. Фільтр працює з інтерфейсом і не вирішує, де зберігати лічильники.
У Redis-режимі збій не перемикає застосунок на локальні ліміти: це порушило б
спільний бюджет між екземплярами API.

## Facade і транзакційна межа: спроби проходження

`AttemptService` надає три операції: почати, прочитати та завершити спробу.
Роботу виконують `AttemptStarter`, `AttemptFinder` і `AttemptCompleter`.
Фасад утримує транзакційну межу та ізоляцію `REPEATABLE_READ`, а контролер
залежить від одного сервісу.

Новий патерн варто вводити, коли він усуває конкретне дублювання або розділяє
незалежні правила. Одна реалізація без потреби підміни не вимагає окремої
ієрархії Strategy; однакові назви CRUD-операцій самі по собі не є підставою
для універсального базового сервісу.
